# 0C-15 — Android 15 dataSync foreground-service timeout

The exact gate command `powershell -NoProfile -File scripts/gate-0c/verify.ps1 -Case android15-timeout` exited `0` on 2026-10-21. The physical P90 (`ANDROID_SERIAL=P90260624026832`) ran Android API 35, `arm64-v8a`, with `com.google.android.webview` 153.0.8010.39. The APK SHA-256 was `f861ab8868d6639012518c5403e9c93e1b6e019b06c548439fc5ec0243ff5dd9`. Full build, instrumentation, and Logcat files remain ignored under `work/android/0c-15/`; instrumentation reported `OK (1 test)`.

The test used the owner-approved rights-cleared Sintel YouTube single `https://www.youtube.com/watch?v=eRsGyueVLvQ`. Instrumentation applied yt-dlp `--limit-rate 32K` only to make a real partial transfer observable. The app targets API 36 and uses the selected `dataSync` service type. Following [Android's foreground-service timeout test procedure](https://developer.android.com/develop/background-work/services/fgs/timeout), the verifier saved `device_config get activity_manager data_sync_fgs_timeout_duration` (`null`), set it to `15000` milliseconds, sent the app Home after a `.part` appeared, and restored the original `null` by deleting the override in a `finally` block. A separate post-run read also returned `null`. No compatibility override was needed for target API 36.

Before Home, item `26f766e3-f8e9-46fc-9112-2ad9f99acc76` was `downloading` at 0% with 31,744 partial bytes, a foreground notification, and a live engine child. About 15 seconds after Home, Android called `Service.onTimeout(startId=1, fgsType=1)`; Kotlin returned the callback to Rust and stopped the service. Rust wrote a `paused` SQLite checkpoint at 3%; the worker exited and retained the `.part`. The test observed notification text **“Downloads paused. Open Zownload to continue.”**, no engine child, and 554,983 partial bytes with the same first-8,192-byte SHA-256 `6fdea32e8a8858239355e4355f00b87675fa003f19cb93da082608b49b21e579`. It brought the existing app task forward and `get_queue` returned the same paused item at 3% in process PID 2220. AndroidRuntime emitted no error in the test Logcat interval.

The first run reached the same timeout, paused state, notification, and preserved media, but its test harness called `startActivitySync` for an Activity Android reused, so instrumentation waited for a new Activity and failed after 45 seconds. The harness was corrected to bring the existing task forward; the full exact verifier then passed. Both runs restored the device's original timeout setting.

This proves the timeout path during one rate-limited real download on the tested Android 15 device. It does not prove a six-hour playlist run or completing the retained `.part` after a later Continue. The Android native corresponding-source/build-input/notice **OPEN RELEASE BLOCKER** and no-distribution rule remain in force.
