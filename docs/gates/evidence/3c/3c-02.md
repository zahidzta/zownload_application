# Gate 3C-02 — Windows updater signing and release workflow

## Implementation record

- `src-tauri/tauri.conf.json` now uses production updater public key fingerprint `6982FF74FE3A85FA` and enables updater artifact creation. The matching private key is stored in the `TAURI_SIGNING_PRIVATE_KEY` GitHub Actions secret; it is not in the repository.
- `.github/workflows/windows-release.yml` builds only x64 NSIS and WiX MSI installers. Pull request builds are unsigned and do not receive signing secrets. A manual release run requires the owner to create an empty draft release first; the workflow uploads to that draft and does not create or publish a release.
- Minisign 0.9 is downloaded from its official Windows release and checked against SHA-256 `2d3d26d635417d0e1177ea7d5e927f66635cea719a6727039d834e1a8a5d0580` before use.

## Local verification

- A temporary Tauri signature verified against the generated public key; changing the signed bytes failed Minisign verification.
- `scripts/verify-windows-release.ps1` passed against the existing signed updater fixture, including the NSIS/MSI metadata keys, signature fields, asset allowlist, and tamper rejection. This exercises the verifier with fixture bytes rather than production-built installer packages.

## V1 asset-URL verifier correction — 2026-11-02

- The first owner-draft V1 run, [41385764585](https://github.com/zahidzta/zownload_application/actions/runs/41385764585), built both Windows installers and verified their signatures and tamper rejection. It then failed because Tauri Action writes updater URLs as GitHub API asset URLs ending in numeric IDs; the verifier incorrectly treated the final path segment as the package filename. The bundle-specific NSIS and MSI mappings in `latest.json` pointed to the correct draft assets.
- The verifier now resolves GitHub API asset IDs through the matching draft-asset ID/name list. A focused regression for bundle-aware API asset URLs passed in Windows PowerShell 5.1 and PowerShell 7 using the signed fixture packages. The corrected production rerun is recorded above.
- The failed run's assets were cleared before the successful rerun. The current draft contains the five verified V1 assets and remains unpublished.
