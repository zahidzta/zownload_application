# 4A-04 — Linux packages, release workflow, and provenance

## V2 evidence

The [release workflow](../../../../.github/workflows/windows-release.yml)
builds only Linux x86_64 AppImage and `.deb` bundles. Its unsigned pull-request
job checks the local package allowlist. Its owner-only signed job starts from
the existing unpublished Windows draft, verifies the Windows assets and
metadata, checks both Linux package signatures and tamper rejection, then
adds the Linux packages and a `linux-x86_64` AppImage updater entry. It compares
the resulting draft with the exact nine-asset desktop allowlist and preserves
the three Windows updater entries. The `.deb` remains a direct-download
install and its release URL must identify the matching `.deb` asset.

**V2 passed for the unpublished `app-v0.0.1` desktop draft.** The signed
[package run](https://github.com/zahidzta/zownload_application/actions/runs/41569451429)
built and signed exactly two Linux packages, rejected tampering, checked the
`.deb` WebKitGTK dependency, and extracted both packages to prove all four
engine files are executable and byte-identical to the verified inputs. It
uploaded only those packages and signatures, then merged the AppImage updater
entry. Its final step rejected GitHub's temporary `untagged-…` draft URL as
though it were a published tag URL; the assets and metadata were already
attached. The corrected verifier passed an offline regression and a local
metadata check, then the owner-only
[draft verification run](https://github.com/zahidzta/zownload_application/actions/runs/41571789659)
passed against the uploaded packages and final `latest.json`. That run checked
the nine-asset allowlist, GitHub asset SHA-256 digests, updater signatures,
tamper rejection, Windows metadata preservation, and the `.deb` asset URL.
The draft remained unpublished. The original Windows metadata is preserved in
[the pre-Linux snapshot](windows-latest-baseline.json).

The first [signed run](https://github.com/zahidzta/zownload_application/actions/runs/41564396468)
stopped before upload: linuxdeploy changed the AppImage `yt-dlp` bytes. A
[second run](https://github.com/zahidzta/zownload_application/actions/runs/41565731872)
with `NO_STRIP=true` still changed them, which isolates the remaining RPATH
rewrite. The workflow now uses a selective `PATCHELF` wrapper for the four
engine resources. The [third signed run](https://github.com/zahidzta/zownload_application/actions/runs/41567348806)
passed signature verification, tamper rejection, and byte-for-byte checks of
all four engines in both packages. It then stopped before upload because a
hash-recording glob also included Tauri's temporary bundle directories. That
glob now selects only the four release files.

The [fourth signed run](https://github.com/zahidzta/zownload_application/actions/runs/41568849298)
stopped during engine preparation because the primary zlib download did not
match its pinned SHA-256. The locked [upstream zlib release asset](https://github.com/madler/zlib/releases/tag/v1.3.2)
was downloaded separately and matched the same
`bb329a0a2cd0274d05519d61c667c062e06990d72e125ee2dfa8de64f0119d16`
digest. The Linux recipe now retries only that versioned, hash-verified
fallback. No asset was uploaded by this run.
