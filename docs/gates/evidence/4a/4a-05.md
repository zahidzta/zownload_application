## `.deb` install and administrator prompt

The package control declared `amd64` and dependencies on
`libwebkit2gtk-4.1-0` and `libgtk-3-0`. The guest's initial APT indexes were
stale and returned 404 for a `libsoup` dependency; `apt-get update` resolved
that environment issue. A clean APT install then displayed the sudo password
prompt and exited 0. `dpkg` reported `ii zownload 0.0.1`; the installed app
opened its GUI, and all four engines were copied from `/usr/lib/Zownload/binaries`
to app data with matching hashes. [Installed app](ubuntu-deb-launched.png).

For the graphical flow, the package was removed from the disposable VM;
`dpkg-query` found no Zownload package and `/usr/bin/zownload` was absent.
GDebi `0.9.5.7+nmu7` then showed **Install Package** with dependencies satisfied,
displayed the administrator authentication dialog for the test user, and
finished the clean install. `dpkg` again reported `ii zownload 0.0.1`.
[Ready](ubuntu-deb-clean-install-ready.png),
[administrator prompt](ubuntu-deb-admin-prompt.png), and
[installation finished](ubuntu-deb-graphical-install-finished.png).
GDebi was added to this cloud VM as a test installer; the stock Ubuntu Desktop
App Center flow was not tested.

A public Archive.org MP3 request from the `.deb` installation failed with

([capture](ubuntu-download-before-close.png)). The running yt-dlp PID `10594`
