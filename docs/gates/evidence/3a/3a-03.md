# 3A-03 — Playlist entry worker

The worker accepts one resolved entry URL and an index, always uses `--no-playlist`, and keeps that index's `.part` file in its own work directory. MP4 Max uses `bv*+ba/b`; MP4 Min uses `wv*+ba/w`. MP3 Max and Min use best source audio and request 320 or 128 kbps through the existing copy/reencode rule. FFmpeg sets the media title and creator and the playlist title as album. Final individual files use collision-safe names; the worker makes no ZIP.

The Windows `playlist_cli` stub integration runs four entries in sequence through an app-data engine path and the pinned FFmpeg binary. It asserts selector arguments, URL isolation, ordered invocations, duplicate-title output numbering, embedded album/title metadata, and 320/128 kbps MP3 output. Gate 3A V1 and the focused `playlist_cli` test passed.

Pinned yt-dlp/QuickJS/FFmpeg observations for all four selector and bitrate profiles were recorded in [Gate 0B MP4](../0b/mp4.txt) and [Gate 0B MP3 playlist](../0b/mp3-playlist.txt). Those probes used the same selectors, direct entry URL model, and pinned binary hashes; this task did not repeat public-network media downloads. 3A-04 connects this worker to the queue and commits the index after each settled entry.
