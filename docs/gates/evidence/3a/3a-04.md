# 3A-04 — Playlist queue lifecycle

The queue now schedules expanded ZIP-off playlists in FIFO order, runs one entry at a time, and commits each entry result and the next resume index together before emitting the updated queue item. Download progress is checkpointed before its event and limited to five updates per second. Pause keeps the current entry and `.part`; resume starts that entry again. Ordinary entry errors increment `failed` and do not stop later entries.

When the playlist settles, any successes create one History row. Partial and all-failed requests persist a translated notification summary in the existing error detail field; all-failed requests create no History row. Fatal disk-full and permission errors stop the playlist, retain their translated error code, and include the success/failure counts. The UI renders both the error and counts in English and Spanish. ZIP-enabled playlist requests remain queued and do not block later eligible ZIP-off work. The public TypeScript/Rust contract is unchanged.

Native fixture analysis exposed a snapshot issue: generic yt-dlp entries use `url` for the direct media file and `webpage_url` for the shared playlist page. Snapshot extraction now prefers an absolute entry `url`, while preserving the video-page fallback used by YouTube flat entries. The regression test covers both forms.
