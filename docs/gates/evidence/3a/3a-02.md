# 3A-02 — Playlist snapshot

The flat extractor response is resolved to ordered HTTP(S) entry URLs and titles. Missing, nested, empty, malformed, or oversized entry lists are rejected. YouTube flat IDs are converted to watch URLs only when the extractor identifies YouTube. A private SQLite v4 row stores the ZIP preference, entry snapshot, and next index by queue ID. The download folder is captured at enqueue. Snapshot creation and each index/counter advance use a transaction; reopening pauses interrupted rows while retaining the snapshot and index. A new queue ID has no snapshot, so History redownload requires fresh expansion.

The queue expands a ZIP-off playlist once in its turn and persists the result before it can run. ZIP-enabled requests remain queued. The queue integration stub confirms that a removed History redownload gets a new ID and fresh expansion.
