## Queue, filesystem, and restart

- Two local public-fixture MP3 requests at 192 and 128 kb/s were enqueued together. State sampling observed at most one active item; the first row disappeared after History was written, then the second began analyzing. Both completed in order. The original progress parser initially interpreted yt-dlp's **pre-download thumbnail conversion** as media post-processing and showed 0% with Stop disabled. The parser now waits for a valid completed media-progress line before entering post-processing. The final native capture shows advancing progress and enabled Stop.
- Clicking Stop in the native UI at 16.8% left `source.webm.part` at 1,029,269 bytes. Changing Settings to a new folder, closing, and reopening kept the row Paused and did not start a transfer. Clicking Continue sent `Range: bytes=1029269-`; the throttled public-fixture server returned HTTP 206 and the transfer completed. The file appeared in the **original captured folder**, with no file in the newly chosen folder.
- Existing names were preserved. Repeated `commons-vorbis` requests produced `commons-vorbis.mp3`, `commons-vorbis (1).mp3`, and later `commons-vorbis (3).mp3`. A History Redownload of the stale MP4 request went straight to Queue while Input remained visible, produced `Building On The Past - High Resolution (1).mp4`, and did not change the first output's hash. History then contained the unique latest request row.
- Setting `downloadDir` to `null` sent a subsequent direct Archive `effect-alarm-siren.mp3` to the system `%USERPROFILE%/Downloads/` folder (151,466 bytes, SHA-256 `4b8f43f094bea43bd23e1996b16b4731db932e0b6352a05ebd49875c4ecb9bfa`). It waited behind the active MP4. Automatic approval review rejected deletion of this test-created Downloads file after its path and hash were verified, so it remains at `C:/Users/zahid/Downloads/effect-alarm-siren.mp3`. No pre-existing Downloads file was touched.
- A missing Archive item generated a durable `not_found` notification before the failed row left Queue. English and Spanish translations were visible. Closing and reopening the native app preserved the error; a later explicit dismissal removed it.

During a separate active-close test, the app process (PID 9124) owned app-data `yt-dlp.exe` PID 22988 and child PID 25068 at 17% transfer. Desktop X returned, the app exited, and after three seconds all three PIDs were absent. The 1,552,832-byte `.part` remained; relaunch showed Paused at 25% and did not auto-resume. UI Cancel removed that queue row and its owned work directory. The independent [Windows process-tree test](native-queue.md) covers timeout, cancel, close, and parent death with a controlled child tree.

## Limits and fixes

This review used one Windows machine, public Archive media, and a throttled HTTP range server serving the checksum-locked Gate 0B Commons fixture. It did not validate every site, a physical disk-full condition, or a permissions failure. The unit error classifier and deterministic queue failure path cover notification settlement; full filesystem resilience and playlist ZIP behavior remain scheduled for 3B. Playlist execution itself remains for 3A. Engine updating remains for 2D.

The native runs exposed and fixed three focused defects in `single.rs` and `queue.rs`: yt-dlp's early thumbnail step mislabeled the download phase; Queue rows showed a raw URL while the worker already knew the title; and Archive's derivative embedded title and converted height did not match the analyzed title and selected quality. The Rust changes use the existing pinned yt-dlp/FFmpeg processes and Tauri events; they add no crate, wire field, or service. The MP4 metadata pass copies streams without recoding after the selected-height conversion, preserving the attached JPEG. The owner's review also replaced the below-History error card with the persistent, dismissible bottom toast; the focused interactive test covers translation, survival through UI and transport restart, visibility over Settings, failed-dismiss retry, and focus after successful dismissal.

Context7 was consulted for React and Tailwind before the toast edit but returned **monthly quota exceeded**.
